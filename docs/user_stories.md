# 사용자 스토리 명세서 (User Stories)

## 개요
본 문서는 Water Log 서비스의 핵심 기능인 **물 섭취 기록 관리**와 **AI 기반 해석 리포트**에 대한 사용자 스토리를 정의합니다.

---

## 1. 물 섭취 기록 (Water Intake Logging)

### 1.1 기록 생성

#### US-001: 간편한 물 섭취 기록
**As a** 바쁜 직장인  
**I want to** 숫자 입력 없이 선택 버튼만으로 물 섭취를 기록하고 싶다  
**So that** 기록에 시간과 노력을 들이지 않고도 내 습관을 남길 수 있다

**인수 조건 (Acceptance Criteria)**
- [ ] 사용자는 ml 단위를 입력하지 않고 선택 버튼으로 기록한다
- [ ] 선택지는 "마셨음", "조금 마셨음", "거의 안 마셨음" 3가지이다
- [ ] 버튼 클릭 즉시 기록이 저장된다
- [ ] 저장 후 즉각적인 피드백(예: 토스트 메시지)이 표시된다

---

#### US-002: 자유로운 기록 횟수
**As a** 수험생 또는 집중이 필요한 사용자  
**I want to** 하루에 기록을 몇 번 하든, 또는 하지 않든 자유롭게 선택하고 싶다  
**So that** 앱 사용에 대한 부담감 없이 내 페이스대로 사용할 수 있다

**인수 조건**
- [ ] 하루 기록 횟수에 제한이 없다 (0회부터 n회까지 가능)
- [ ] 기록하지 않은 날에 대한 경고나 알림이 없다
- [ ] "streak(연속 기록)" 개념이 존재하지 않는다

---

#### US-003: 실패 없는 경험
**As a** 기존 물 섭취 앱에서 이탈 경험이 있는 사용자  
**I want to** 기록을 빠뜨려도 실패로 간주되지 않기를 원한다  
**So that** 죄책감 없이 지속적으로 앱을 사용할 수 있다

**인수 조건**
- [ ] 기록하지 않은 날은 "데이터 없음"으로 표시된다
- [ ] "목표 미달", "실패" 등의 부정적인 메시지가 표시되지 않는다
- [ ] 기록 누락 후에도 앱에 재방문할 수 있는 긍정적인 UI를 제공한다

---

### 1.2 기록 조회

#### US-004: 과거 기록 타임라인 조회
**As a** 사용자  
**I want to** 내가 언제 물을 마셨는지 시간 순서대로 확인하고 싶다  
**So that** 내 물 섭취 패턴을 시각적으로 이해할 수 있다

**인수 조건**
- [ ] 기록한 물 섭취 내역이 시간 순서대로 표시된다
- [ ] 각 기록에는 날짜, 시간, 섭취량 수준이 표시된다
- [ ] 스크롤을 통해 과거 기록을 조회할 수 있다

---

#### US-005: 캘린더 뷰로 기록 확인
**As a** 시각적 정보를 선호하는 사용자  
**I want to** 캘린더 형식으로 한 달 간의 기록을 한눈에 보고 싶다  
**So that** 내가 어느 날에 물을 잘 마셨는지 빠르게 파악할 수 있다

**인수 조건**
- [ ] 월간 캘린더 뷰가 제공된다
- [ ] 각 날짜에 기록 여부가 시각적으로 표시된다
- [ ] 날짜를 선택하면 해당일의 상세 기록을 확인할 수 있다

---

#### US-006: 특정 기간 기록 필터링
**As a** 데이터 분석에 관심 있는 사용자  
**I want to** 특정 기간(예: 지난 주, 지난 달)의 기록만 필터링해서 보고 싶다  
**So that** 특정 시기의 패턴을 집중적으로 분석할 수 있다

**인수 조건**
- [ ] 날짜 범위를 선택할 수 있는 필터가 제공된다
- [ ] "최근 7일", "최근 30일" 등의 프리셋 옵션이 있다
- [ ] 커스텀 날짜 범위 선택이 가능하다

---

### 1.3 기록 수정 및 삭제

#### US-007: 기록 삭제
**As a** 사용자  
**I want to** 잘못 입력한 기록을 삭제하고 싶다  
**So that** 정확한 데이터만 유지할 수 있다

**인수 조건**
- [ ] 각 기록에 삭제 버튼이 제공된다
- [ ] 삭제 전 확인 메시지가 표시된다
- [ ] 삭제 후 즉시 UI에서 제거된다

---

## 2. AI 기반 해석 리포트 (AI-Powered Interpretation Report)

### 2.1 리포트 생성

#### US-008: AI 리포트 자동 생성
**As a** 내 기록이 어떤 의미인지 알고 싶은 사용자  
**I want to** AI가 내 물 섭취 패턴을 분석하고 해석해주기를 원한다  
**So that** 단순한 숫자가 아닌 의미 있는 변화를 이해할 수 있다

**인수 조건**
- [ ] 최소 3일 이상의 데이터가 있을 때 리포트 생성이 가능하다
- [ ] 리포트는 주 1회 자동으로 생성되거나 사용자 요청 시 생성된다
- [ ] Gemini API를 통해 자연어 형태의 리포트가 생성된다
- [ ] 생성된 리포트는 데이터베이스에 저장된다

---

#### US-009: 공감적이고 비평가적인 톤의 리포트
**As a** 평가받기 싫어하는 사용자  
**I want to** AI 리포트가 나를 비판하지 않고 관찰과 해석 중심으로 작성되기를 원한다  
**So that** 리포트를 읽는 것이 부담스럽지 않고 도움이 된다고 느낄 수 있다

**인수 조건**
- [ ] 리포트에 "목표 미달", "실패", "부족" 등의 부정적 표현이 없다
- [ ] "완벽하진 않았지만..." 등의 공감적 표현을 사용한다
- [ ] 관찰 → 해석 → 가벼운 제안 순서로 구성된다
- [ ] 강요하지 않는 톤으로 작성된다

---

#### US-010: 맥락 기반 패턴 분석
**As a** 사용자  
**I want to** AI가 내 물 섭취를 요일, 시간대, 컨디션과 연계해서 분석해주기를 원한다  
**So that** 어떤 상황에서 물을 잘 마시는지 또는 못 마시는지 이해할 수 있다

**인수 조건**
- [ ] 물 섭취 패턴을 요일별로 분석한다
- [ ] 시간대별 패턴을 분석한다
- [ ] 컨디션 메모(피로, 붓기 등)가 있다면 이를 연계해서 해석한다
- [ ] 예: "물이 적었던 날에 피로 메모가 자주 등장했어요"

---

### 2.2 리포트 조회

#### US-011: 생성된 리포트 목록 확인
**As a** 사용자  
**I want to** 과거에 생성된 모든 리포트를 목록으로 보고 싶다  
**So that** 시간에 따른 변화를 비교하고 확인할 수 있다

**인수 조건**
- [ ] 리포트 목록 페이지가 제공된다
- [ ] 각 리포트는 생성 날짜와 제목이 표시된다
- [ ] 최신 리포트가 상단에 표시된다

---

#### US-012: 리포트 상세 내용 확인
**As a** 사용자  
**I want to** 특정 리포트를 선택해서 전체 내용을 읽고 싶다  
**So that** AI의 해석과 제안을 자세히 이해할 수 있다

**인수 조건**
- [ ] 리포트를 클릭하면 상세 페이지 또는 모달이 표시된다
- [ ] 리포트의 전체 텍스트가 읽기 편한 형식으로 표시된다
- [ ] 리포트가 기반으로 한 기간 정보가 명시된다

---

#### US-013: 수동 리포트 생성 요청
**As a** 특정 시점에 분석이 필요한 사용자  
**I want to** 주간 자동 생성을 기다리지 않고 즉시 리포트를 생성 요청하고 싶다  
**So that** 필요한 시점에 즉각적으로 인사이트를 얻을 수 있다

**인수 조건**
- [ ] 리포트 페이지에 "리포트 생성" 버튼이 제공된다
- [ ] 버튼 클릭 시 Gemini API 호출을 통해 리포트가 생성된다
- [ ] 생성 중에는 로딩 상태가 표시된다
- [ ] 생성 완료 후 자동으로 새 리포트가 표시된다

---

## 3. 선택적 기능 (Optional Features)

### 3.1 컨디션 메모

#### US-014: 컨디션 입력 (선택)
**As a** 컨디션 변화에 관심 있는 사용자  
**I want to** 하루 한 번 간단하게 내 컨디션을 기록하고 싶다  
**So that** AI 리포트가 더 정확하고 의미 있는 해석을 제공할 수 있다

**인수 조건**
- [ ] 하루 최대 1회 컨디션 질문이 표시된다 (Opt-in)
- [ ] "오늘 컨디션은 어땠어?", "붓기나 피로를 느꼈어?" 등의 질문이 제공된다
- [ ] 선택지 형식이며, 응답하지 않아도 된다
- [ ] 입력된 컨디션 데이터는 AI 리포트 생성 시 활용된다

---

### 3.2 맥락 기반 알림 (향후 적용 가능)

#### US-015: 알림 설정 (기본 OFF)
**As a** 물 마시기를 잊어버리는 사용자  
**I want to** 원하는 시간대에만 부드러운 알림을 받고 싶다  
**So that** 집중을 방해받지 않으면서도 물 마시기를 상기할 수 있다

**인수 조건**
- [ ] 알림은 기본적으로 비활성화되어 있다
- [ ] 사용자가 직접 활성화할 수 있다
- [ ] 시간대만 지정 가능하다 (예: 오후 3–5시)
- [ ] 알림 톤은 권유형/허용형이다 (예: "지금 한 모금 정도면 충분해요")

## 4. 비기능 요구사항 (Non-Functional Requirements)

### NFR-001: 성능
- 물 섭취 기록은 500ms 이내에 저장되어야 한다
- AI 리포트 생성은 30초 이내에 완료되어야 한다
- 기록 조회 페이지는 1초 이내에 로드되어야 한다

### NFR-002: 접근성
- 모바일 반응형 디자인을 지원해야 한다
- 주요 기능은 3탭 이내에 접근 가능해야 한다

### NFR-003: 데이터 보안
- 사용자의 물 섭취 기록과 컨디션 데이터는 암호화되어 저장되어야 한다
- Supabase RLS 정책을 통해 사용자는 자신의 데이터만 조회할 수 있어야 한다

### NFR-004: 사용성
- 앱 사용에 대한 학습 곡선이 최소화되어야 한다
- 모든 주요 액션은 명확한 피드백을 제공해야 한다

---

## 5. 제외 기능 (Out of Scope)

다음 기능은 현재 버전에서 제외됩니다:
- ❌ 로그인/회원가입 기능 (요청에 따라 제외)
- ❌ 정확한 ml 단위 수분 섭취 측정
- ❌ 게임/캐릭터/경쟁 중심 동기부여 시스템
- ❌ 의료·치료 목적의 수분 관리 기능
- ❌ 주간 요약 공유 기능 (향후 P2로 고려)
- ❌ 홈 위젯 (향후 P2로 고려)

## 6. 성공 지표

| 지표 | 목표 | 측정 방법 |
|------|------|-----------|
| 7일 유지율 | 60% 이상 | 설치 후 7일 내 재방문 비율 |
| 기록 부담 인식 | "귀찮다" 응답 30% 이하 | 사용자 설문 |
| AI 리포트 조회율 | 80% 이상 | 생성된 리포트 오픈 비율 |
| 무기록 후 재방문율 | 50% 이상 | 기록 누락 후 24시간 내 재방문 비율 |
